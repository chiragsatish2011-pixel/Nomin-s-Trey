# Security & Privacy Architecture Notes — Bluey for Windows

This document outlines the privacy guarantees, data flows, and security model enforced in the Windows PC Edition of Bluey.

---

## 1. Zero-Disk Sensory Data Guarantee

Bluey requires visual and auditory perception to act as an effective focus buddy. However, Bluey is architected with strict in-memory guarantees:

1. **Screenshots Never Hit Disk:**
   - Display captures are downscaled in-memory to a maximum width of 1024px and compressed as JPEG (~70 quality) directly in RAM.
   - Screen buffers are processed immediately and discarded. No screenshot file, temporary image, or raw frame buffer is ever saved to disk or persistent storage.
2. **Audio Never Hits Disk:**
   - Microphone input is recorded in-memory via `MediaRecorder` in the sandboxed hidden microphone window.
   - Audio chunks are transcribed in RAM and immediately zeroed/released. No `.wav`, `.mp3`, or audio temporary files are written to disk.
3. **No OCR Text Logging:**
   - Text extracted by optical character recognition is bounded to active window context and kept in volatile process memory during inference.
   - Neither the OCR text nor raw perceptual strings are ever written to disk, application logs, or telemetry files.

---

## 2. Secrets Management & DPAPI Encryption

- **API Key Storage:**
  - The user's NVIDIA NIM API key is stored using Windows DPAPI (Data Protection API) via Electron's `safeStorage` subsystem (`CryptProtectData`).
  - The encrypted ciphertext is tied to the current Windows user login credentials. It cannot be read or decrypted by other user accounts on the machine.
  - The key is **never** written to `settings.json`, config files, or Git repositories.
- **Process Isolation:**
  - The API key is stored strictly within the Node.js Main process.
  - The key is **never transmitted to any renderer window**. Renderers only receive a boolean flag indicating whether a key is configured (`hasKey()`).

---

## 3. Network Boundaries & AI Model Traffic

- **Single External Endpoint:**
  - The **only** outbound network traffic generated by Bluey is HTTPS communication with `https://integrate.api.nvidia.com/v1` for NVIDIA NIM vision classification and nudge phrasing.
  - No analytics, telemetry, tracking, or crash-reporting packets are sent to third parties.
- **Payload Contents Sent to NVIDIA NIM:**
  - The in-memory downscaled screenshot (JPEG, max 1024px width).
  - Bounded OCR text extracted from the screen.
  - Current foreground application process name and window title.
  - User's declared focus task description string.
  - Session elapsed time and idle mouse seconds.
  - Up to 8 previous categorical classifications (e.g. `on_task`, `off_task`).
- **Prompt Injection Defense:**
  - Screen text is explicitly treated as **untrusted user data**. The classifier prompt instructs the model to ignore instructions found within screen captures and treat them strictly as context for task evaluation.

---

## 4. Window & Process Hardening

- **Electron Security Flags:**
  - All four BrowserWindow instances (`face`, `overlay`, `dashboard`, `mic`) run with:
    - `contextIsolation: true`
    - `nodeIntegration: false`
    - `sandbox: false` with strictly typed preload IPC bridges.
- **Content Protection:**
  - Bluey windows apply `win.setContentProtection(true)`.
  - This prevents Bluey's own windows (speech bubbles, face widget, debug overlays) from appearing in screen captures, avoiding recursive loops and self-classification artifacts.
- **Click-Through Overlays:**
  - The notification overlay runs with `win.setIgnoreMouseEvents(true, { forward: true })`, ensuring that notifications and pointing animations never intercept clicks or interfere with the user's workflow.

---

## 5. Screen Sharing & Sensitive Data Protocol

> [!WARNING]
> **Pause Before Sharing / Password Entry**
> Because Bluey samples the screen every 10–30 seconds during an active session, users must pause Bluey before entering sensitive credentials (e.g. recovery phrases, unmasked passwords) or initiating screen shares in video conferences.
> 
> Press **`Ctrl + 2`** anytime to immediately pause the session and suspend screen capture until you are ready to resume.
